# Yatk コンセプト

## 目的

Yatk は、C#/.NET 向けの単一プロセス内で動作する軽量なインメモリジョブスケジューラである。
目的は、限られたCPU・I/O・外部サービスなどの資源を安全に共有しながら、多数のバックグラウンド処理を「ほどほどにやっとく」ことである。
高可用性や分散実行ではなく、
「あとでやっといて」
「このジョブは並列2本まで」
「全部終わったら教えて」
のような、アプリケーション内部のバックグラウンド処理をシンプルに扱うことを目指す。

## 設計思想

Yatk は Task.Run の代替ではなく、その一段上の抽象を提供する。
単なる非同期実行ではなく、

- ジョブの管理
- 並列度制御
- 実行状態の観測
- キャンセル
- 優先度
- Graceful Shutdown

を統一的に扱う。

一方で、Hangfire や Quartz.NET のような永続ジョブシステムにはならない。

## スコープ

Yatk が扱うのは、「単一プロセスで完結するジョブ実行」のみである。
ジョブはインメモリで管理され、プロセス終了とともに失われる。

## 対象ユースケース

例えば、

- 外部プロセスの長時間にわたる呼び出し（たとえば ffmpeg による動画変換など）
- 大容量ファイルコピー
- HTTP API 呼び出し
- DB 更新
- 定型的なバッチ処理
- スレッドセーフでないライブラリの実行制御

などを、適切な並列度で安全に実行する。

## ジョブモデル

ジョブは 一回限りの実行要求である。
一度投入されたジョブは再投入できない。
ジョブには一意の JobId が割り当てられ、

- 状態取得
- キャンセル
- 進捗取得

などは JobId を通じて行う。

## 実行モデル

ジョブは Execution Lane（実行レーン） 上で実行される。各レーンは独立した実行制約を持つ。
例えば、

- ThreadPool 上で並列4本
- ffmpeg 用レーンは2本
- 専用スレッドレーンは常に1本

などを自由に構成できる。ジョブは投入時に実行レーンを選択する。

## ジョブの種類

Yatk は二種類のジョブ投入方法を提供する。

### リッチジョブ

クラスとして実装する。
ジョブ固有のロジックや状態メッセージ、進捗報告などを記述できる。

### ラムダジョブ

`scheduler.Do(async ct => ...);`

のように簡単に投入できる。内部では通常のジョブとして扱われる。

## 観測可能性

ジョブは常に観測可能である。

利用者は、

- 現在の状態
- 実行中ジョブ一覧
- 待機中ジョブ一覧
- 進捗
- 状態メッセージ

を取得できる。状態変化イベントも利用できる。

## 目指さないもの

Yatk は以下を目的としない。

- 分散ジョブ実行
- クラスタリング
- 永続キュー
- Cron スケジューラ
- ワークフローエンジン
-  BPM
- GUI ワークフロー設計
- Exactly Once 保証
- プロセス再起動後のジョブ復元

これらが必要なら、Hangfire や Durable Task Framework などを利用する。

## 名前の由来

Yatk = 「やっとく」
利用者は
「これやっといて」

という感覚でジョブを投入できる。
Yatk は、その仕事を適切なタイミング・適切な並列度・適切な実行先で消化する。
